# 公開魚画像データの監査結果

- 監査日: 2026-10-29
- 対象: 魚の頭・尾検出用Mendeleyデータ、魚体領域抽出候補AutoFish
- 目的: 「魚の頭・尾の位置」「魚体領域」「捌き工程」のどの実験に使えるかを見極める

## 結論

1. **頭・尾の位置検出の小さなベースライン候補はMendeley。** YOLO形式の箱があり、200枚をローカルで全数確認できた。撮影条件は一枚岩ではなく、公開説明とラベルファイルのクラス数に1件ずつ差がある。境界に触れる箱は小数丸め誤差の範囲内。ランダム分割の性能値を実運用の性能とみなさない。
2. **魚の全身マスクを試す候補はAutoFish。** データカードによれば魚体マスク、境界箱、魚ID、長さ、魚種、表裏情報がある。アジ類（horse mackerel）を含むが、ベルト上の俯瞰・多魚体画像であり、まな板上の一匹を捌く映像とはドメインが違う。
3. **捌き工程の認識データはどちらにもない。** 工程名や「頭を取った」「三枚おろし中」などの時系列ラベルは確認できない。スマホ視点で独自に撮影し、魚・撮影セッション単位で分割する必要がある。

## Mendeley: 頭・尾検出

取得元の説明では200画像、学習160枚、テスト40枚、合計1,308注釈。YOLO形式、CC BY 4.0と記載されている。ローカルの展開物は以下のとおり。

| 項目 | 学習 | テスト | 合計 |
|---|---:|---:|---:|
| JPG画像 | 160 | 40 | 200 |
| YOLOラベル付き画像 | 160 | 40 | 200 |
| head (class 0) | 592 | 132 | 724 |
| tail (class 1) | 481 | 103 | 584 |
| head + tail 注釈 | 1,073 | 235 | 1,308 |

`classes.txt` は `head`, `tail` の順。画像サイズは `832×624` が117枚、`624×832` が83枚で、縦横が混在する。完全一致する画像ファイルのSHA-256重複は見つからなかった。

### 品質・分割上の注意

- 18個のYOLO箱（学習側14画像）は、小数値から境界を再計算するとごくわずかにフレーム外へ出る。ただし最大超過は0.00042ピクセルで、座標の小数丸めで説明できる大きさ。実質的な切れや学習前に必要な修正とは判断しない。
- 学習側のクラス内訳は公開ページの記述（591 head / 482 tail）と比べ、実ファイルでは1個ずつ逆方向にずれる（592 / 481）。テスト内訳132 / 103は一致する。総注釈数は一致するため、誤植か個別ラベル差かは公開データだけでは断定できない。
- 200枚中85枚でhead数とtail数が一致しない。複数魚・重なり・画面端・遮蔽・注釈漏れのいずれかは画像ごとの再確認が必要で、片方が見えないことを「切除済み」と読み替えてはいけない。
- 画像ファイル名に日付が含まれ、7つの撮影日が学習・テストの両方に現れる。完全一致画像はなかったが、近接撮影・似た個体が分割をまたぐ可能性がある。実アプリを評価するときは撮影日、魚個体、セッションごとにホールドアウトする。
- 見た目は、単体魚を布・台に置いた写真と、複数魚が重なった写真が混在する。頭・尾の位置検出補助には使えるが、手・包丁・まな板が入った捌き場面の代表データではない。

### 注釈プレビュー

赤枠はhead、青枠はtail。選んだ画像だけの可視化であり、検出モデルの推論結果ではない。

ローカルで確認したサンプルでは、赤枠がhead、青枠がtailを示す。画像本体は公開リポジトリには含めない。

## AutoFish: 魚体領域抽出

公式データカードには1,500画像、454個体、18,160個のインスタンスセグメンテーションマスク、25グループと記載されている。魚はコンベア上で撮影され、Cod / Haddock / Whiting / Hake / Horse mackerel / Otherを含む。個体は各グループのいずれか一つにだけ属するため、実験時は同一個体の漏れを避けてグループ単位で分割できる。Set1・Set2は魚が重ならない配置、Allは高い重なりを意図した配置。

この作業では15.9 GBの全画像を取得せず、55,035 byteの `metadata.csv` をローカルで確認した。

- 行数と固有画像名は1,500で、25グループを含む。
- CSVの魚数合計は18,158。公開データカード／大学の研究データページが記す18,160マスクと2件差がある。CSVと説明のどちらかを正しいと決めつけず、実際にマスクを使う段階で対応ファイルを確認する。
- CSVの列は画像パス、`total_fish`、魚種別の魚数。**ピクセルマスクや境界箱そのものではない。** 学習には公式画像と注釈データの対応関係も取得する必要がある。
- 小さな `example_images/*.png` は取得を試したが、配布先ホストの名前解決／リダイレクト取得に失敗し、ローカル保存できなかった。今回は画像そのものではなく、公式カードとメタデータで適合性を評価した。

アジ類の検出や魚体輪郭の予備学習には有望。ただし、魚を一匹だけ近距離で撮るスマホ動画にそのまま性能を外挿できない。まず公式の注釈付きサンプルを開き、元画像・マスクの対を目視してから必要なグループのみ取得する。

## 捌き工程への適用判断

公開候補は「魚の形・部位」を学ばせる補助データ。工程認識に必要な以下の教師データは含まれない。

- 切る前、頭を外した後、内臓処理後、三枚おろし中などの、利用者が合意した工程ラベル
- 手・包丁・魚体の相対位置や、まな板上の画角
- 画面外、手や道具による遮蔽、魚体の一部欠損を区別するラベル
- 同じ魚を工程順に追う動画・フレーム時刻・魚個体ID

まずはスマホ動画からキー画像を作り、工程ラベルは利用者が手動で確定する。画面に頭が映っていないだけでは「頭を切り落とした」としない。詳細な項目とテンプレートは [`phone-capture/README.md`](../phone-capture/README.md) を参照。

## 実施範囲と未実施

- 実施: Mendeley 200枚すべての画像・YOLOラベル対応、クラス数、画像寸法、境界はみ出し、完全一致ファイル重複の確認。サンプル画像の箱重ね表示。
- 実施: AutoFishのCSV全1,500行を読み、画像数・グループ数・魚数合計を確認。
- 実施: HOG特徴＋ロジスティック回帰で、正解枠から切り出した頭・尾画像の分類実験。撮影日単位のテストで75.8% crop accuracy。これは全画面の検出ではない。手順・指標・誤分類画像は [`../../ml/hog-experiment-report.md`](../../ml/hog-experiment-report.md)。
- 未実施: 全画面の物体検出・セグメンテーションの学習と精度測定。CPU PyTorchの導入は空き容量不足で停止し、AutoFishの画像・マスクサンプルも取得できていない。したがって、捌き工程でのモデル精度は示していない。
- 推奨する次の実験: 容量に余裕のあるPython学習環境を用意し、まず撮影日単位のtrain/validation/test分割で全画面head/tail検出器を学習する。公式160/40分割の値は比較用に分離して報告し、境界の小数丸めだけを理由に箱を修正しない。さらに別撮影日のスマホ実画像で評価する。
