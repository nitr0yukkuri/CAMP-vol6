# サーモン工程モデル用データ調査

調査日: 2026-11-04  
目的: サーモンの下処理ガイドで工程の進み具合を推定するため、公開データの適合性・利用条件・次の収集方法を整理する。

## 結論

サーモンをスマートフォンで撮影し、家庭の下処理工程を工程ごとに注釈した公開データは見つからなかった。魚の検出・輪郭抽出や工場のフィレ品質検査データはあるが、うろこ取り、頭を外す、内臓を取って洗う、骨・皮の処理といった工程認識の教師データとは異なる。

そのため、今見つかった外部データだけでサーモン工程モデルを学習したり、実用精度を主張したりはできない。CC0表示の教材動画はデータ処理の試作に使える可能性があるが、まず映像本体と利用条件を確認する。実運用条件の評価にはiPhone 15で撮影した独立した魚・撮影セッションのデータが必要。

## 最新mainのガイドとモデルラベルのずれ

最新 `main` のサーモンガイドは、うろこ、頭、内臓・洗浄、片側の身、反対側の身、必要に応じた骨・皮の6工程。骨・皮は最後にまとめて扱い、完了ボタンは利用者が押す。工程分類器は5つの既知状態 `whole` / `head_removed` / `gutted` / `filleting` / `finished` と、拒否用の `unknown` を持つ。ガイドの各工程と分類ラベルは一対一ではない。

- うろこを取る前後はどちらも `whole` 相当。現行の静止画像分類では、うろこ取りの完了を見分けられない。
- 頭を外した状態、内臓を取って洗った状態、身を外している途中、身を分けた状態は、粗い状態候補として既存ラベルに対応する。ただし実写の学習行がないため、サーモンで判定できる根拠はまだない。
- 骨・皮の要否や処理完了はガイドもAI判定対象としていない。骨・皮を残す選択、取り除く作業中、処理後を混ぜて `finished` の正解にしない。

作業中の動作と、作業後の魚の状態は別の教師信号。静止画像へ「うろこ取り中」と付けても、時間方向の動作モデルを学んだことにはならない。次の収集データでは両方を分けて記録する。

- `guide_step_id`: `salmon_scale` / `salmon_head` / `salmon_guts` / `salmon_first_side` / `salmon_second_side` / `salmon_bones`
- `current_action`: `not_started` / `in_progress` / `likely_complete` / `unknown`
- `step_outcome`: `complete_confirmed` / `skip_confirmed` / `unknown`。骨・皮は「不要で飛ばした」と「処理済み」を区別する。
- `fish_state`: 撮影者が確認した `whole` / `head_removed` / `gutted` / `filleting` / `finished` / `unknown`
- `fish_id`, `session_id`, `relative_time_ms`: 同じ魚の連続性と時刻
- `visibility`: `visible` / `occluded` / `out_of_frame` / `unknown`
- `review_status`: 人が画像とラベルの一致を確認したか

映像に工程が映らない場合は `unknown` とし、モデル候補を正解ラベルへ自動コピーしない。

## 収集と評価の進め方

1. ZPE教材の映像本体を公式ページから開き、CC0表示・対象魚・実際に映る工程・取得可能性を記録する。映像を確認できなければ、素材を得たものとして扱わない。
2. 既存の研究用撮影画面を使い、iPhone 15で少数のパイロットを撮影する。最新ガイドの6つの `guide_step_id` を記録し、1匹を一つの `fish_id` で追い、各工程の前後と作業中の代表フレーム、遮蔽・画角外・照明条件を記録する。画像は画面の案内どおり端末内で管理する。
3. 撮影者が工程と結果を確認してラベルを確定する。専門家レビューがない間は、手順そのものの正しさや安全性を検証済みと表現しない。
4. 学習・検証・テストはフレーム単位でランダムに分けず、魚とセッションをまたがない単位で分割する。独立した魚・撮影回が十分にそろう前は精度評価を公表しない。
5. 頭・尾検出、工程動作、工程後の状態判定を別タスクとして評価する。条件別に再現率、誤検出、工程遷移の遅延を報告し、未知・見えない状態を既知の工程へ押し込まない。

現時点で工程モデルは学習しない。まずラベル仕様と撮影サンプルを確定し、データ量・クラス分布・権利が確認できた段階で学習器を選ぶ。MediaPipeはブラウザー上の推論ランタイムであり、工程データを自動で用意したり学習したりするものではない。

## プロジェクト内の確認結果

- `data/phone-capture/capture-manifest.csv` はヘッダーのみで、実撮影行は0件。
- `ml/prepare_stage_capture.py` と `ml/train_stage_classifier.py` は5つの既知状態と拒否用 `unknown` を扱うが、最新ガイドの6工程を独立判定するモデルではない。
- 公開済みの `head-tail.tflite` は頭・尾検出用で、サーモン工程分類モデルではない。
- したがって、現段階では「サーモンを学習済み」とは言えない。
